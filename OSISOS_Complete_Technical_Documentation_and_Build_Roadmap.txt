Executive SummaryOSISOS is a modular operating environment built above the Linux kernel. Linux supplies low-level mechanisms—scheduling, virtual memory, networking, device drivers, filesystems and system calls. OSISOS supplies its own APIs, shell, process/resource management, filesystem management, IPC, concurrency, networking management, users/security, service management, logging, configuration and system utilities.The defining constraint is resource efficiency. The project targets approximately 32 MB RAM, a single low-frequency CPU-class core and a small storage footprint. These are engineering targets to measure, not claims of actual PlayStation 2 hardware compatibility.Core principle:Linux provides mechanisms; OSISOS provides abstractions, policies, management and the user environment.2. ObjectivesComplete OS environment rather than unrelated scripts.Process, memory, filesystem, IPC, concurrency, networking, security, service and system-management subsystems.CLI-first operation with no required desktop environment.PS2-class resource-envelope testing.Bootable QEMU image.Measured RAM, CPU, storage, boot-time and networking benchmarks.Linux-specific details isolated behind wrapper/platform interfaces.Portable core architecture suitable for future architectures.3. Non-ObjectivesDo not rewrite Linux's scheduler, VM system, TCP/IP stack or driver ecosystem.Do not target actual PS2 hardware during the semester.Do not make GUI functionality core.Do not place Python/Node runtimes in the core image.Do not begin with bootloader work.4. Kernel StrategyStart from a known QEMU-compatible configuration.Keep boot, storage, console and networking drivers required for the target.Remove unused drivers/features only after a working baseline exists.Keep debug features in development images; strip release artifacts where appropriate.Avoid kernel modifications unless they have a clear project purpose.Keep custom kernel patches/modules isolated and documented.23. BusyBox StrategyBusyBox is useful as a compact reference or base utility provider. OSISOS must not simply become a renamed BusyBox distribution: OSISOS-specific commands should demonstrate the OSISOS API and wrapper architecture.24. Performance OptimizationMinimize dependencies.Prefer C/small libraries for core components.Build only required features.Strip release binaries.Measure binaries with size/readelf.Avoid unnecessary background polling.Use on-demand services.Use bounded buffers.Avoid unnecessary IPC/network copies.Use bounded/circular logging.Measure RSS and total system memory, not just binary size.25. Security and ReliabilityUse dedicated users for services where possible.Centralize privileged operations.Validate shell and network input.Use Linux permissions/capabilities rather than inventing unnecessary parallel mechanisms.Apply process/service resource limits.Keep logs bounded.Reap child processes.Make optional service failure non-fatal.Handle disk-full and low-memory conditions cleanly.Prevent uncontrolled service restart loops.26. Final Project DefinitionOSISOS is a modular, resource-constrained Linux-based operating environment that exposes core operating-system functionality through a unified abstraction layer. It combines process and memory management, filesystem management, IPC and concurrency, networking, shell management, service management, users/security, system management and resource accounting while deliberately targeting a PS2-class hardware resource envelope.
