Phase 1 • Early Boot Flow

The Boot Journey: Bare Metal to C

How OSISOS transitions from BIOS execution through GRUB into 32-bit Protected Mode and C execution.

Boot Chain Steps
  1. 01
    BIOS / UEFI: Loads GRUB bootloader from CD-ROM ISO or virtual disk.
  2. 02
    Multiboot Handshake: GRUB verifies magic 0x1BADB002 in first 8KB of boot.S.
  3. 03
    Protected Mode Transition: GRUB disables interrupts, enters 32-bit mode, and loads ELF at 1MB.
  4. 04
    Kernel Stack Setup: boot.S allocates 16KB stack and passes magic & memory pointer to C.
  5. 05
    C Entry (kernel_main): GDT, IDT, PIC remapping, and memory management online.
Core Hardware Setup (GDT, IDT & PIC)
arch/i386/gdt.c Descriptors
// 5 Global Descriptors (Flat 4GB)
0x00: NULL Descriptor
0x08: Kernel Code (Ring 0, Exec/Read)
0x10: Kernel Data (Ring 0, Read/Write)
0x18: User Code (Ring 3, Exec/Read)
0x20: User Data (Ring 3, Read/Write)
0x28: Task State Segment (TSS)
arch/i386/pic.c Interrupts
// PIC Remapping (Avoid CPU Faults)
Master PIC: 0x20 -> IRQ 0..7
Slave PIC: 0x28 -> IRQ 8..15

// IDT Table Configuration
Vectors 0..31: CPU Exceptions
Vectors 32..47: Hardware IRQs
Vector 0x80: System Call Trap

Remapping the dual 8259 PIC is critical: x86 CPU exceptions naturally occupy vectors 0-31. Without remapping, timer ticks and keyboard presses would trigger false Double Faults or General Protection Faults!

Phase 2 • Core Subsystems

Memory Management: PMM, Paging & Heap

Three-tier memory hierarchy: 4KB frame tracking, virtual memory with NULL-pointer trap, and dynamic kernel heap.

1. Physical Memory (PMM)

Manages all physical RAM frames using an ultra-compact bit array.

8,192
4 KB Page Frames (32 MB)
  • •
    Bitmap consumes only 8 KB of RAM (1 bit per 4KB frame).
  • •
    First 4MB identity reserved for kernel code, stack, and page tables.
2. Virtual Memory & Paging

Two-level paging directory enabled via the CPU CR0.PG and CR3 registers.

// NULL Page Protection
void paging_guard_null_page() {
  /* Unmap Page 0 (0x000-0xFFF) */
  page_table_0[0] = 0;
  flush_tlb();
}

Defensive Architecture: Null pointer dereferences immediately trigger hardware Page Fault (#PF) rather than silently corrupting memory.

3. Kernel Heap (KHeap)

Dynamic memory allocation for network packets, sockets, and buffers.

  • •
    Boundary-Tag Allocator: Implements kmalloc() and kfree() with header/footer tags.
  • •
    Coalescing: Merges adjacent free blocks during kfree() to prevent heap fragmentation.
  • •
    Bounded Growth: Heap is isolated from kernel code and physical frame buffers.
Phase 3 • Process Scheduler

Preemptive Multitasking & Context Switching

Round-robin scheduling driven by the 100 Hz Programmable Interval Timer (PIT) interrupt.

Context Switch Mechanism

Every 10 milliseconds, the timer interrupt rips execution away from the running task:

arch/i386/switch.S Assembly Context Switch
irq0_timer_isr:
  pushal ; Push EAX, ECX, EDX, EBX, ESP, EBP, ESI, EDI
  mov %esp, (%eax) ; Save old task ESP into PCB
  mov (%edx), %esp ; Load next task ESP from PCB
  call pic_send_eoi ; Acknowledge PIC interrupt
  popal ; Restore all registers of new task
  iret ; Pop EIP, CS, EFLAGS -> Resume task!

The CPU's hardware interrupt stack frame (EIP, CS, EFLAGS) combined with software pushal creates a complete, reproducible snapshot of any running process.

Dual Kernel Task Architecture
PID 1
Interactive Shell

Runs user command loop, keyboard input processing, file manipulation, and user programs.

PID 2
Network Poller

Drains Intel E1000 RX rings, handles TCP timeouts/retransmissions, and serves HTTP and echo requests.

True Concurrency: While a user is typing a shell command, PID 2 concurrently downloads files, retransmits TCP segments, and responds to incoming web traffic.

PCI Bus Enumeration

Brute-force scan of the PCI configuration space via I/O ports 0xCF8 (Address) and 0xCFC (Data):

// 256 buses × 32 slots × 8 funcs
for (bus=0; bus<256; bus++)
  for (slot=0; slot<32; slot++)
    id = pci_read(bus, slot, 0);
    if (id == 0x8086) /* Intel */
      detect_nic(bus, slot);

Detects Base Address Registers (BARs), MMIO addresses, and enables Bus Mastering for DMA.

Intel E1000 Gigabit NIC

  • •

Phase 8 • Network Autoconfiguration

Dynamic Configuration: DHCP & DNS

Zero manual setup: plug into any network and obtain IP leases and domain name resolution.

DHCP Client State Machine

Fully autonomous 4-stage lease negotiation on UDP ports 68 (Client) & 67 (Server):

DISCOVER Broadcast on 255.255.255.255 requesting IP configuration
OFFER Router offers IP (e.g. 10.0.2.15), Netmask, Gateway, and DNS
REQUEST OSISOS accepts offer and requests lease confirmation
ACK Lease bound! Timer schedules automatic lease renewal at T1

Engineering Reflections

Debugging War Stories & Hurdles

Tackling low-level bugs where standard debuggers (gdb, valgrind) are completely unavailable.

Hurdle 1: Console Corruption During Scrolling

The Bug: When the terminal scrolled up, line 2 would periodically glitch and display scrambled characters.

Root Cause: The 100Hz timer ISR was printing a live heartbeat directly to Row 2 of the VGA buffer. When user typing triggered a scroll, the asynchronous timer interrupt wrote in the middle of the line copy!

Fix: Eliminated raw VGA writes inside timer ISR; migrated uptime and status tracking to system variables and sysinfo.

Hurdle 2: VirtualBox vs QEMU PCI Identification

The Bug: Networking worked flawlessly in QEMU, but VirtualBox reported "No E1000 Card Found".

Root Cause: QEMU defaults to Device ID 0x100E (82540EM), whereas VirtualBox uses 0x100F (82545EM) or 0x1004 (82543GC).

Fix: Implemented is_e1000_device() matching the complete Intel 8254x PCI ID family, enabling zero-config boot in both hypervisors.

Hurdle 3: Memory Exhaustion Under High Packet Rates

The Bug: Running rapid ping or HTTP requests caused kmalloc failures within 30 seconds.

Root Cause: Received Ethernet packets were allocating fresh heap buffers, but unacknowledged socket queues weren't reclaiming memory on EOF.

Fix: Implemented bounded RX ring buffers and aggressive socket idle timeouts (SVC_IDLE_TICKS), stabilizing memory usage under 2MB.

Hurdle 4: VirtualBox ACPI Shutdown Freeze

The Bug: shutdown command powered off QEMU immediately, but hung VirtualBox in an infinite halt.

Root Cause: QEMU uses port 0x604, while VirtualBox uses ACPI PM1a_CNT port 0x4004.

Fix: Added multi-port power-off sequence: outw(0x604, 0x2000), outw(0xB004, 0x2000), and outw(0x4004, 0x3400).
